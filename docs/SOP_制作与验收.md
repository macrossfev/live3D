# 虚拟人（RPM → 奥特曼）制作与验收 SOP

> 版本 v1.0 · 2026-08-18
> 范围：以 Ready Player Me 全身模型为骨架载体，按 T-pose 立绘制作奥特曼外观，
> 最终接入 ultraman-web 游戏引擎。
> 姊妹文档：`SOP_Mixamo建模.md`（Blender 建模侧）

---

## 0. 现状盘点（本 SOP 的出发点）

### 已解决 ✅
| 模块 | 结论 | 证据 |
|---|---|---|
| 骨架与动画 | RPM 81 骨全身 GLB + Mixamo FBX 直接重定向（剥 `mixamorig` 前缀 + 厘米→米） | Boxing.fbx 播放，骨四元数实时变化，帧差 7-24% |
| 蒙皮管线原型 | 立绘正交投影逐顶点上色（绑定矩阵数学修正后） | 红 4.55% 落在正确高度带（肩 4.6%/胸盾 10.6%/腰盆 21.2%） |
| 素材 | `assets/rpm/avatar_full.glb`（VR-Demo 库提取）、`assets/heroes_tpose/*.png`（6 英雄） |  |

### 未解决 ❌（本 SOP 的核心目标）
1. **头部/脸**：三条路线均未过关——球体堆（丑）→ 组合头盔（脸不对）→ 克隆头壳（炸屏）
2. 视觉验收方法：我（agent）无直接视觉能力，视觉模型描述已两次虚构结果

### 已确立的技术事实（不要重新踩）
- RPM 头是**独立网格 `Wolf3D_Head`**（2123 顶点），身体 `Wolf3D_Body` 无头
- RPM 全身像是 **A-pose**（手臂下垂），立绘是 T-pose → **手臂不可投影，只能骨权重配色**
- SkinnedMesh 顶点世界坐标 = `Σ wᵢ·(boneWorld·boneInv)·bindMatrix·v`，不能用节点矩阵直变换
- GLB 有**孤立垃圾顶点**（y=176 / y=-1），一切范围统计必须按索引引用过滤
- FBXLoader 会把 `mixamorig:Hips` 净化成 `mixamorigHips`（冒号消失）
- Blender(Debian 3.4.1)：Cycles 无头烘焙全黑；`img.save()` 必须先 `pack()`；像素缓冲自底向上
- WebGL `toDataURL` 快照通道不可靠，**验收截图一律用 agent-browser 页面截图**
- 发布目录禁止中文/空格文件名（page-publish 会拒收）

## 1. 角色与职责

| 角色 | 谁 | 职责 |
|---|---|---|
| 制作 | agent | 按 §2 流水线实现；每阶段跑 §3 自动门；产出 §4 验收包 |
| 验收 | **用户** | **唯一的视觉质量裁决者**。看验收包，逐项 ✓/✗ |
| 视觉模型 | 外部 LLM | 仅允许做 §5.2 定义的受限辅助，**禁止作为通过依据** |

**铁律：**
1. 自动门（§3）全绿 + 用户人工验收（§4）通过 = 该阶段完成。缺一不可。
2. 我说"我看过没问题"无效——我没有视觉。一切视觉结论的来源只能是像素统计或用户。
3. 自动门未过的版本**禁止发布**（v5"身体没了"就是没过 G2 就发布的教训）。

## 2. 制作流水线（五阶段，每阶段独立过门）

```
A 素材与标定 → B 身体蒙皮 → C 头部方案 → D 动画 → E 游戏集成
                     └──────── C 阶段需先做 §5 决策实验 ────────┘
```

### 阶段 A：素材与标定
**输入**：`heroes_tpose/<hero>.png`（768×1360 透明 PNG）+ `avatar_full.glb`
**步骤**：
1. 透明 bbox + 关键行扫描（头顶/眼/下颚/颈/肩/胸/腰/盆/裆/膝/踝/脚）
2. 骨骼世界坐标表（Hips/Spine2/Neck/Head/LeftArm/LeftLeg/LeftFoot）
3. 建立分段锚点 `Z2Y`（身高→图片y）+ 水平比例 `SX`（**骨盆带宽标定**，姿势无关）
**门**：G1（几何完整性）

### 阶段 B：身体蒙皮
**步骤**：
1. 隐藏除 `Wolf3D_Body` 外全部网格（衣物/毛发/眼镜/齿/眼球/头原件/重复件）
2. 逐顶点：主权重骨为手臂系 → 程序配色（肩+上臂红/前臂+手银）；其余正面 → 立绘采样；背面 → 程序纹（红脊线/肩胛带/颈后红）
3. 垃圾顶点过滤（索引引用 + 合理范围 0<y<2.2, |x|<1.2）
**门**：G2（渲染存在性）+ G3（空间落位）+ G5（人脸清除）

### 阶段 C：头部方案 ⚠️ 先做 §5 决策实验
**门**：G6（无遮挡物）+ G2 + 用户重点验收脸部 checklist

### 阶段 D：动画
**步骤**：Mixamo FBX → 剥前缀 → Hips 位置轨 ×0.01 → AnimationMixer
**门**：G4（动画活性）

### 阶段 E：游戏集成
**步骤**：HERO3D 加 GLTFLoader 分支；六英雄共用骨架换配色/头盔；动作文件全换 Mixamo FBX
**门**：G1-G6 + 游戏内冒烟（打一题 → 出拳 → 命中）

## 3. 自动验收门（全部可脚本化，发布前必须全绿）

| 门 | 名称 | 判据（默认阈值，可调） | 防的事故 |
|---|---|---|---|
| G1 | 几何完整性 | 骨骼=81；网格清单符合预期；非流形边<50；孤立顶点已过滤 | 模型损坏 |
| G2 | 渲染存在性 | **8 个高度带各自的身体覆盖 ≥3%**（头/胸/腰/盆/左右大腿/左右小腿位置都有实体像素） | **"身体没了"（v5）** |
| G3 | 空间落位 | 红色像素分布带与预期模式匹配：肩带红>0、胸盾带红>5%、腰盆带红>10%、小腿带红<1%、膝带银 | 颜色涂错位（v3/v4） |
| G4 | 动画活性 | 冻结前后 LeftArm 四元数变化 >0.01；连续帧差 3-25% | 动画静默不动（mixamorig 前缀事故） |
| G5 | 人脸清除 | 肤色像素（130>r>g>b 类肤色聚类）<0.1% | 人脸裸渲染（v3 发现的 Wolf3D_Head 事故） |
| G6 | 无遮挡异常 | 画面任一单色物体占比 <60%；全屏均亮 <120 | **壳糊满屏（v4）** |
| G7 | 标准验收包 | §4 的 8 视角截图完整生成且非纯色 | 截图通道坏（toDataURL 事故） |

**执行方式**：一个 `tools/acceptance_check.py`（或页内 eval 脚本）跑完输出 JSON 报告，附在验收包里。

## 4. 人工验收包（每阶段产出，用户看这个）

### 固定拍摄规范（可复现，禁止随手角度）
- 冻结动画（pose t=0）+ 统一光照 + 1280×900
- 8 视角：正 / 背 / 左 / 右 / 左34 / 右34 / 俯视 / 仰视
- **并排对照板**：左=参考立绘（同高度裁切），右=渲染图，中间画对齐参考线（眼线/肩线/膝线）

### 用户 checklist（每项 ✓/✗/备注）
```
□ 身体完整（有躯干/四肢/手/脚）
□ 整体配色分区与立绘一致（红银位置）
□ 胸口计时器：位置/颜色/形状
□ 头部轮廓：盔型/头冠脊
□ 眼睛：大小/形状/上挑角度/发光
□ 下颚红区：位置/形状
□ 手部：颜色/细节
□ 动作：打拳自然度（D 阶段起）
```
**通过标准**：无 ✗，或用户明确说"接受此瑕疵"。
**否决标准**：任一 ✗ → 写明哪项 → 回到对应阶段修改，重走该阶段两道门。

## 5. 头部方案决策实验（蒙皮 vs LLM）

### 5.1 路线 A：蒙皮/几何（程序化，可控）
| 子路线 | 做法 | 风险 | 成本 |
|---|---|---|---|
| A1 UV 重绘 | 导出 `Wolf3D_Head` UV 展开图 → 在 UV 上画初代头盔纹（银底/杏仁眼/下颚红）→ 贴图回贴，保留人头几何 | 鼻子/耳朵几何在侧光下露馅（纹理盖不住形状） | 中 |
| **A2 几何替换（推荐主力）** | 隐藏人头 + 独立头盔建模（Blender Skin 修改器已有完整经验与验证工具链）→ 导出 GLB → 挂 Head 骨（挂接方式已验证） | 建模质量依赖迭代轮数 | 中高，但每步可数值验证 |
| A3 混合 | RPM 头几何 + 拉普拉斯平滑融五官 + 重投影（v3-v5 的克隆壳路线） | **世界→局部写回数学不稳，两轮失败** | 已沉没，除非解决写回否则不碰 |

### 5.2 路线 B：LLM 辅助（受限使用）
**允许的用法**：
1. **参数提取**（一次性的事实读取）：从立绘提取设计参数表（眼睛长宽比/上挑角度/下颚红高度/头冠起点）→ 转成数字 → 人工核对后喂给 A 路线
2. **二元粗筛**：只回答"图中有/没有 X"类问题（如"头顶是否有一条纵脊 Y/N"），且同一问题问 3 次取多数

**禁止的用法**：
- 开放式评价（"效果如何？"）→ 已两次得到虚构的"一切正常"
- 作为验收依据 → 验收只能走 §3 + §4

### 5.3 决策实验设计
1. 同一基准（阶段 B 完成的身体 + 固定相机）
2. A1 与 A2 各出一版头部
3. 同一验收包（8 视角 + 对照板）交用户**盲选**（文件名去标识）
4. 胜者进入阶段 D；若都不行 → 收集用户具体否决项 → 细化参数再各一轮（上限 2 轮，防止无限迭代）
5. B 路线全程只做参数提取，不参与制作

### 5.4 预判（诚实版）
- A2 几何替换成功率最高：建模-渲染-截图循环里**每个环节都能数值验证**（包围盒/覆盖率/带分布）
- A1 有鼻梁露馅的先天风险，但最省事，值得先出样品
- 眼睛/下颚红的**精确定位**建议用 B1 参数提取（立绘上量像素）+ 人工核对，不要凭感觉

## 6. 版本管理与回滚

- 每次发布：git commit + page-publish 版本号 + sha256 + 当次验收报告存档 `docs/acceptance/`
- **已知好版本**：动画首次跑通版（RPM+boxing+组合头盔，用户评"整体有点像了"）
- 线上出问题：`page-publish --slug index-612e62ba966f0f98 --switch <N>` 即刻回滚，再修
- 工具页（rpm_ultraman.html）每次改动前先 `cp` 存 `tools/archive/`（v2 组合头盔版没存档导致无法回退的教训）

## 7. 附：一句话教训墙

1. 没过自动门的版本不发。
2. 我看不见图，视觉模型会编——像素统计和用户才是真相。
3. 蒙皮网格的世界坐标必须走绑定矩阵。
4. 一切范围统计先过滤孤立顶点。
5. 头是 `Wolf3D_Head`，别再满模型找。
6. 手臂 A-pose 没法投影，骨权重配色。
7. 截图验收用 agent-browser，不用 toDataURL。
8. 立绘是真理来源，参数从它身上量，不要凭感觉调。
